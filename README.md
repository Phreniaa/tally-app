# Tally

Tally is a private, browser-only habit log. It has no build step and no
third-party dependencies, so it can be opened directly from `index.html` or
served as a static site.

## Project layout

- `index.html` contains the document structure, accessible labels, dialogs,
  and inline SVG symbols.
- `styles.css` contains design tokens, layout, responsive rules, and component
  styles. Prefer existing CSS variables over adding one-off colours.
- `app.js` contains state, persistence, rendering, event handling, and habit
  calculations.
- `manifest.webmanifest` and `icon.svg` support installation and browser
  identity.

## Making changes safely

1. Find the relevant `render...`, `open...`, or `save...` function before
   editing markup generated by JavaScript.
2. Keep user data compatible with `normHabit()` and update `exportData()` if
   the saved format changes.
3. Escape user-entered text with `esc()` whenever it is inserted into an
   HTML template.
4. Use the existing `data-act` event delegation pattern for new controls
   instead of attaching handlers to every rendered row.
5. Keep rendering side-effect free where possible: update state, call `save()`,
   then call the smallest relevant render function.

## Quick checks

Editing the JavaScript should still pass a syntax check:

```powershell
node --check .\app.js
```

Then open `index.html` and verify: create a habit using the short form, expand
More options when you need schedule or appearance controls, mark it done, edit
a day, switch views, export data, import using both replace and merge, and
reload the page. On keyboard, verify skip navigation, arrow-key tab
navigation, visible focus, modal focus trapping, completion controls, and
Enter-to-open details from a Grid day.

Habit editing also supports a per-habit monthly rest-day limit (four by
default) and a “Start new phase” action that archives the current definition
while starting a fresh history from today.

The optional “Why it matters” text appears before completion, while the
optional “Shown when it's done” text appears after completion. The Daily view
also exposes an “Add a note…” action before or after completion; notes remain
date-specific and continue to appear in the Logbook and Grid details.

The masthead and backup banner make the local-only storage model visible.
Stats use continuity-oriented labels such as “Fully handled days”; keep those
labels consistent when adding new metrics.
